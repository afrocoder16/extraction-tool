## Findings to address before integration or release

### 1. Approval and verification can refer to obsolete text — high priority

`engine/build_book.py:157` reads verification and approval by page number alone. `engine/serve.py` saves new transcripts without invalidating those records. The reviewer also allows an approval while edits are unsaved.

Reproduced with a temporary book: create a verified, approved transcript; change its text; build again without re-verifying. The result still reports `production_ready: true`.

Bind review and verification to the transcript revision/hash and source image hash. Edits, re-OCR, colour changes, or source changes must invalidate the relevant approval. Saving and approving need to be one consistent operation or a strictly ordered pair.

### 2. Completeness is derived from potentially incomplete statistics — high priority

`engine/build_book.py:149` derives expected content pages only from entries already in `page_stats.json`. `total_pages` is placed in metadata but is not used to prove that every source page was classified.

Reproduced: a declared two-page book with only page 1 analysed, transcribed, verified and approved reports ready. Require an authoritative source-page inventory, classification coverage for every page, and explicit dispositions for blanks, illustrations and intentionally excluded pages. Reject an empty or partial release unless a separately named excerpt was requested.

### 3. Red-text assignment is only partly deterministic — high priority

The mask and Tesseract word redness are deterministic. Claude still chooses output span colours from visual and textual hints; there is no enforced text-to-pixel alignment in `transcribe.py`. The export's `red_assignment` description overstates this guarantee.

`engine/verify.py:153` compares aggregate red proportions. Incorrectly colouring different words can preserve the same ratio. Missing mask files produce a null measurement without an explicit missing-evidence flag. Add word/character alignment evidence, uncertain-colour states, and required-evidence checks. A paragraph bounding box from dots cannot determine individual red words.

### 4. Current validation cannot establish transcription accuracy — high priority

`engine/verify.py:168` approximates line count using span count, and its mismatch flag fires only when no Ethiopic text exists. Partial omissions can pass. Tesseract similarity and a model's own uncertainty are useful review signals, but are not independent accuracy measurements. There is no manually verified OCR benchmark in the tests.

Measure literal character errors, omitted/added lines, reading order, numeral and punctuation accuracy, red-span alignment, and human correction time against scan-based reference transcriptions.

### 5. A book with no section table exports zero sections — medium priority

The README/docstring promises one implicit section when `sections` is empty. `build_book.py` actually puts every block in `front_matter` and returns an empty section list. Reproduced in a temporary book. Implement and test the promised fallback before supporting arbitrary new books.

### 6. App references and model provenance need stronger guarantees — medium priority

Block IDs are generated from section position (`engine/build_book.py:134`), so inserting or moving blocks can change later IDs. The global model field comes from configuration, although the corpus includes Tesseract drafts and manual transcription. Store stable IDs, edition/source identity, per-page model revision and extraction parameters, and an explicit correction history.

### 7. Several assumptions are specific to Wudase Mariam — medium priority

The transcription system prompt names this book; colour/blank thresholds are tuned to this scan; script checks reject all Latin letters and ASCII digits; clipping permits only top/bottom edges. The hosted reviewer fixes `BOOK_ID` and `MAX_PAGE=218`. Different Orthodox books need profiles, legitimate mixed-script exceptions, left/right/gutter clipping, multi-column handling, and configurable book routing. Amharic and Ge’ez share script, so script detection alone must not assign language.

### 8. Review storage and hosted publication need work for multiple reviewers

Local saves directly overwrite JSON, and hosted saves replace a page or the complete review map without revision conflict checks. Add atomic local writes, revision checks, append-only history and an import command for hosted edits. Imported approvals must be rechecked against exact local source/transcript revisions.

The build copies scans and transcripts into static public paths. Authentication protects the functions, but the repository does not show server-side access protection for those static files. A client-side sign-in overlay alone is not file access control. Decide explicitly whether the published baseline is public; protect static assets separately if private review is intended. No deployed site's access settings were inspected.
